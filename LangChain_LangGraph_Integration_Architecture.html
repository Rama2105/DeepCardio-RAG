LangChain & LangGraph Integration Architecture

Transforming the Multi-Modal Cardiac Analysis Platform

Prepared for N Rama Rao · March 27, 2026

1. Executive Summary

This document outlines how integrating LangChain and LangGraph would transform the DeepCardio-RAG multi-modal cardiac analysis platform. Currently, the project uses hand-built RAG pipelines with hardcoded retrieval, GPT-2 with manual soft-prompt injection, and linear pipeline execution. With LangChain/LangGraph, the system gains production-grade RAG with proper vector stores, swappable LLM backends (GPT-4o, Claude, Llama), stateful multi-agent workflows with conditional branching, and built-in observability.

Key takeaway: LangChain replaces the broken RAG and limited LLM layer. LangGraph transforms rigid linear pipelines into intelligent, stateful, multi-agent workflows. Your custom PyTorch models (the real innovation) remain exactly as they are — they just get wrapped as LangChain Tools.

3. What LangChain Brings

3.1 Replacing the Broken RAG Pipeline

The current pipeline in core/pipeline.py has a critical issue: get_collection() always returns None, so Milvus never works. Every request falls back to two hardcoded mock guidelines. LangChain fixes this fundamentally:

Current Code (core/pipeline.py)

class ClinicalKnowledgeRetriever:
    def __init__(self):
        self.collection = get_collection()  # Always returns None!

    def retrieve_context(self, query_embeddings, top_k=3):
        if self.collection is None:  # Always True
            return ["Hardcoded guideline 1", "Hardcoded guideline 2"]

With LangChain

from langchain_community.vectorstores import FAISS
from langchain_huggingface import HuggingFaceEmbeddings

# Load clinical guidelines from multiple sources
splitter = RecursiveCharacterTextSplitter(chunk_size=500)

# Create a REAL working vector store

vectorstore = FAISS.from_documents(docs, embeddings)
retriever = vectorstore.as_retriever(search_kwargs={"k": 5})

4. What LangGraph Brings

LangGraph is the game-changer. While LangChain handles RAG components, LangGraph turns your linear pipelines into intelligent, stateful workflows with conditional branching, parallel execution, and human-in-the-loop checkpoints.

4.1 The Core Concept: StateGraph

Currently, each pipeline runs as a fixed linear sequence. LangGraph replaces this with a directed graph where each node is a processing step, and edges can be conditional:

from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Literal

# Define the state that flows through the entire graph
class CardiacAnalysisState(TypedDict):
    # Inputs
    patient_id: str
    modalities: dict           # Raw input data per modality

    # Processing outputs
    embeddings: dict            # Per-modality embeddings from CNN encoders
    model_predictions: dict     # CNN/Fusion model outputs
    retrieved_guidelines: list  # RAG-retrieved clinical context

    # Final outputs
    clinical_report: str
    risk_level: str
    alert_triggered: bool
    requires_review: bool       # Human-in-the-loop flag

4.2 The Cardiac Analysis Graph

This single LangGraph workflow replaces ALL current linear pipelines (ECG, Echo, Heart Sound, VFDB, CardioFusion) with one intelligent graph:

def build_cardiac_graph():
    graph = StateGraph(CardiacAnalysisState)

    # ---- Node 1: Input Router ----
    def route_input(state):
        mods = [k for k, v in state["modalities"].items() if v is not None]
        state["active_modalities"] = mods
        return state

    # ---- Node 2: Parallel Encoding ----
    def encode_modalities(state):
        embeddings = {}
        for mod in state["active_modalities"]:
            encoder = get_encoder(mod)  # Your existing CNN encoders!
            embeddings[mod] = encoder(state["modalities"][mod])
        state["embeddings"] = embeddings
        return state

    # ---- Node 3: Fusion Decision ----
    def should_fuse(state) -> Literal['fuse', 'single']:
        return "fuse" if len(state["active_modalities"]) > 1 else "single"

    # ---- Node 4a: CardioFusion (multi-modal) ----
    def run_fusion(state):
        model = get_cardiofusion_model()
        state["model_predictions"] = model.inference(state["embeddings"])
        return state

    # ---- Node 5: RAG Retrieval (LangChain) ----
    def retrieve_guidelines(state):
        query = build_query_from_predictions(state["model_predictions"])
        docs = retriever.invoke(query)  # LangChain retriever!
        state["retrieved_guidelines"] = [d.page_content for d in docs]
        return state

    # ---- Node 6: Risk-Based Routing ----
    def assess_risk(state) -> Literal['critical', 'review', 'normal']:
        risk = state["model_predictions"].get("cardiac_risk_score", 0)
        if risk > 80: return "critical"
        elif risk > 50: return "review"   # Needs human cardiologist
        return "normal"

    # ---- Node 7: Report Generation (LangChain LLM) ----
    def generate_report(state):
        chain = report_prompt | llm | parser
        state["clinical_report"] = chain.invoke({...})
        return state

    # ===== WIRE THE GRAPH =====
    graph.add_node("route", route_input)
    graph.add_node("encode", encode_modalities)
    graph.add_node("fuse", run_fusion)
    graph.add_node("single", run_single_analysis)
    graph.add_node("retrieve", retrieve_guidelines)
    graph.add_node("report", generate_report)
    graph.add_node("alert", trigger_alert)
    graph.add_node("review", flag_for_review)

    graph.add_edge(START, "route")
    graph.add_edge("route", "encode")
    graph.add_conditional_edges("encode", should_fuse,
        {"fuse": "fuse", "single": "single"})
    graph.add_edge("fuse", "retrieve")
    graph.add_edge("single", "retrieve")
    graph.add_edge("retrieve", "report")
    graph.add_conditional_edges("report", assess_risk,
        {"critical": "alert", "review": "review", "normal": END})

    return graph.compile()

4.4 State Persistence and Human-in-the-Loop

LangGraph can pause at any node (e.g., waiting for a cardiologist to review a borderline case) and resume later. This is impossible with the current linear pipeline:

from langgraph.checkpoint.sqlite import SqliteSaver

# Persist graph state to SQLite (survives server restarts)
checkpointer = SqliteSaver.from_conn_string("data/cardiac_graph.db")
app = graph.compile(checkpointer=checkpointer)

# Start analysis (may pause at human review node)
config = {"configurable": {"thread_id": "patient_12345"}}
result = app.invoke(initial_state, config)

# Later: cardiologist provides review and graph resumes
if result["requires_review"]:
    app.update_state(config, {
        "cardiologist_notes": "Confirmed borderline EF. Recommend follow-up.",
        "approved": True
    })
    final = app.invoke(None, config)  # Resume from checkpoint

6. What Stays The Same (Your PyTorch Models)

LangChain/LangGraph does NOT replace your deep learning models. All your custom neural networks remain exactly as they are — they get wrapped as LangChain Tools:

EchoVideoEncoder (R2+1D)KEPT AS-ISWrapped as LangChain Tool, called by Echo Agent
ECGImageClassifier (2D-CNN)KEPT AS-ISWrapped as LangChain Tool, called by ECG Agent
HeartSoundClassifierKEPT AS-ISWrapped as LangChain Tool, called by Sound Agent

CardioFusion (Transformer+MMoE)KEPT AS-ISWrapped as LangChain Tool, called by Fusion Agent

The wrapping is minimal:

from langchain_core.tools import tool

@tool
def analyze_ecg_signal(signal_path: str) -> dict:
    """Analyze a 12-lead ECG signal and return arrhythmia classification."""
    signal = load_ecg_signal(signal_path)
    encoder = get_model().encoder  # Your existing 1D-CNN
    embedding = encoder(signal)
    return {"embedding": embedding, "classification": classify(embedding)}

@tool
def run_cardiofusion(modality_data: dict) -> dict:
    """Run multi-modal CardioFusion analysis."""
    model = get_cardiofusion_model()  # Your existing hybrid model
    return model.inference(modality_data)

7.2 Real-Time Streaming

The frontend shows progress as each graph node completes, instead of waiting for the full result:

@app.post('/api/analyze/stream')
async def stream_analysis(request):
    async for event in app.astream(state, config):
        # Frontend sees each step live:
        # "Encoding ECG signal..."
        # "Retrieved 5 clinical guidelines"
        # "Generating report with GPT-4o..."
        yield ServerSentEvent(data=json.dumps(event))

7.3 Automatic LLM Fallback Chains

llm_with_fallback = ChatOpenAI(model='gpt-4o').with_fallbacks([
    ChatAnthropic(model='claude-sonnet-4-20250514'),  # If GPT-4o fails

7.4 LangSmith Observability

Every LLM call, retrieval query, and agent decision is automatically traced. You can see exactly why the system made a particular diagnosis, how long each step took, and how much it cost. Essential for medical AI auditing.
